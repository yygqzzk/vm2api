# 测试结果中心：调度控制

入口：**虚拟机 → 测试结果中心**。每槽展示最近 30 次测试，**左新右旧**；点击色块查看本次回答、当时的判定规则和调度影响。

## 快捷操作

- **关闭调度**：转为人工关闭，不关机、不清凭证、不强制中断在途请求。
- **开启调度**：沿用槽位原有的人工开启校验；新测试从零观察，其他系统限制仍可能阻止接单。
- **解除停调**：只解除测试策略自己的阻断，保留凭证故障、维护、代理和额度限制。
- **转人工关闭**：接管自动停调，后续成功的测试不会重新开启槽位。

顶部支持搜索、状态筛选和显式勾选后的批量配置。

## 配置自动策略

在槽位的 **规则设置** 中：

1. **结果判定**：按预期字符串判断内容。未启用时，绿色只代表调用成功。
2. **自动调度**：启用策略，选择停止条件、连续次数和自动恢复次数。

默认建议是：**连续 3 次待定停止调度；停调后连续 2 次成功解除测试停调**。

可选停止条件：待定、内容不通过、调用失败。勾选多个条件时，按连续命中其中任意条件的次数计数，不是各条件分别累计。
阈值须为正整数。关闭自动恢复后，只能人工解除停调。

启用策略前必须启用本槽的定时测试。只按内容结果停调时，还须启用结果判定规则。
策略默认关闭；保存未启用的策略可作为草稿。策略作用于整个槽位，不按模型分别停调。

## 结果与计数

| 情况 | 计数使用的结果 |
| --- | --- |
| 调用失败 | 调用失败，不算黄色待定 |
| 调用成功，未启用内容判定 | 成功（绿色） |
| 调用成功，内容匹配通过 | 成功（绿色） |
| 调用成功，内容判定待定 | 待定（黄色） |
| 调用成功，内容判定不通过 | 内容不通过（红色） |

只统计**定时测试**。手动测试仍留历史，但不推进也不中断自动计数；色块提示会标明来源与是否参与计数。

- 正常观察时，不符合停止条件的定时结果中断停调计数。
- 自动停调后，只统计恢复所需的连续成功；非成功结果中断恢复计数。
- 人工关闭优先，不推进自动开关计数；人工重新开启后从零观察。
- 修改策略、判定规则或定时计划后重新计数。修改前开始的测试不参与新策略，不回算旧历史。
- 自动停调期间继续使用原有定时计划复测，不需要打开网页。真实复测会消耗账号额度。
- 最近 30 条是展示/留存上限，不是计数窗口；清理旧报告不会丢失已持久化的计数。

## 保护与故障处理

自动恢复只删除 `test_schedule_hold`，不会调用人工开启路径，也不会清除其他限制。

- 暂停或删除定时计划，不会自动放行已停调的槽位；恢复前需重新启用定时测试或人工解除。
- 修改已停调槽位的规则，不会立即放行。
- 停用仍处于停调或等待动作的策略，必须明确选择转人工关闭或解除测试停调。
- 配置、计数和待执行决策保存在 SQLite；VM 标记通过原子文件写入落地，启动时核对未完成动作。
- 写入失败会展示动作错误，下次定时测试或重启时重试；也可人工关闭接管。
- 槽位归属变化会停用原自动策略，旧任务不得改变新归属下的调度。
- 槽位重建不会绕过已存在的测试停调。

测试详情中的调度影响是该次执行的证据；当前状态和最近重试结果以槽位行显示为准。

## 批量与权限

批量配置会展示目标数量并要求确认。只复制自动策略，不复制测试题、模型、时间、运行计数和人工调度状态。
启用前置条件或目标权限有任一不满足时，不保存任何目标的配置；落地动作失败会单独提示，不冒充成功。

- `admin`：配置全部可见槽位。
- `user`：仅配置和操作自己的槽位。
- `super`：保留现有人工调度权限，可解除测试停调；自动策略配置只读。

API 位于 `/api/panel/fork/test-reports/auto-schedule`，人工开关复用 `/api/panel/vms/:id/schedulable`。
