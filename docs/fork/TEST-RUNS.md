# 测试结果中心（fork）

## 功能

虚拟机列表的「测试结果中心」默认展示全部可见槽的定时、面板手动测试记录，按开始时间倒序。支持槽位、来源、内容判定、精确模型 ID 筛选及服务端分页（每页50条）；每槽最多留存30条，两种来源合计。另有「按槽摘要与规则」页签看最新结果、配置规则。槽位测试页也能查看本槽记录和配置规则。

点击记录行的「查看」就地展开正文、调用指标、命中/缺失字符串、请求参数与规则版本快照。列表不传完整正文、Prompt和规则快照，展开才加载详情。模型输出按纯文本显示，不执行 HTML。时间按浏览器时区显示，不改变计划原有调度时区。打开的列表每30秒刷新，也可手动刷新。

## 判定规则

每槽一份独立规则，默认关闭。启用后，填写每行一个预期字符串，可选全部包含 / 任意包含；字面匹配、区分大小写、首尾去空白，最多20条，每条500字符。未满足时默认「待定」，可主动选择「不通过」。支持把当前规则复制到可见的同平台槽，但不复制 Prompt；操作前必须确认目标槽使用同一道测试题。

- 调用成功并且完整的可见回答命中规则：通过。
- 完整回答未满足规则：按该次规则的设置判为待定或不通过。
- 没启用规则、调用失败、空回答、token截断、缺少可信终止原因、无法确认完整的截断样本：始终待定，不因这些情况判账号异常。
- 不匹配推理/思考文本、工具参数、错误对象或序列化 JSON。Responses 收集器可能在没有终止事件时补出 `body.status=completed`，不能用它证明样本完整。

执行状态 `ok` 和内容 `verdict` 分开。一条调用成功的记录可以内容不通过；超时/认证失败仍是调用失败、内容待定。规则通过只代表满足你设置的字符串条件，不能单独证明账号“满血”或“降智”。

规则在调用开始时快照，判定在可见正文截为2000字符的展示摘要之前执行。优先从测试返回体中提取正文，绕开上游 `result.text` 的4000字符显示上限；只剩截断文本而无法确认完整时待定。匹配后的命中/缺失字符串和原因随记录保存，不随规则修改而重写。没有自动重判历史。

## 数据和兼容性

程序集中在 `src/lib/fork/test-reports/` 和 `web/src/features/fork/test-reports/`。上游接入点只负责初始化、定时测试结果回调、手动测试包装、权限/路由分发及面板入口；不修改协议转发、闭源 kernel、调度热路径、重试或计费。

记录表 `fork_test_reports` 复用原 SQLite。迁移文件独立放在本模块目录，版本为 `001forktests`，复用原迁移执行器与校验机制，不占上游 `048` 等纯数字版本。规则存在原 settings 表的 `fork_test_rule:<vm-id>`，不扩展上游计划配置格式。之前草稿的逐槽 JSON 历史从未发布，不为它做兼容迁移。

仅新增受控的结果记录，不增加模型调用。不采集后台健康探测或普通 API 请求，不依赖请求日志 Debug 模式，不复制原始响应/头/凭证/执行日志。会持久化测试 Prompt 快照（最多16000字符，超出会标记截断）、模型参数及可见回答，它们属于私有运行数据，数据库及备份沿用现有访问控制，不提交到仓库。

定时记录仍遵守原任务版本门禁：运行中改写/删除计划、停止 runner，旧任务不回写结果。删除定时计划清除它的定时记录，手动记录和规则保留；删除槽位清除该槽全部记录和规则。升级前没有留存的正文不补采。租户只访问当前归属自己槽位的数据；super只读，admin/master可读写。

## 自动调度不在本版

本版不写 `schedulable`、不增删 hold、不改配额/凭证状态，也不预置自动动作框架。后续若实现连续失败隔离、连续通过恢复，须单独确认阈值、隔离状态归属、复测路径、账号换票后的归属和人工操作优先级；恢复不能解除人工停调或其他模块的故障限制。
